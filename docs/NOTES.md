# Notes

How the port is made and checked. For building and running the tests see
[BUILDING.md](../BUILDING.md); for the menus and preferences see [SHELL.md](SHELL.md).

## The idea

Both games were written in C and 68k assembly for the Mac (THINK C / CodeWarrior style A5 world,
no symbols). The port rewrites every function in C and runs it on a small native Toolbox
(`mactb/`), with SDL2 underneath. Nothing of the original code runs in the game.

The test rig (`harness/`) runs the original code under Musashi with a high-level Mac OS. The rig
and the port share the same Toolbox code, so any difference between the original and the C is in
the game code, never the platform.

## How the C is checked

Each C function is checked two ways (`tools/verify_subs.sh`, `verify_all.sh`, `verify_original.sh`):

- **Per call**: at every call the C version runs on the real inputs, its writes are recorded and
  undone, then the original runs, and the two must agree: registers (as far as callers can see
  them), every byte written.
- **End to end**: a whole game with the C in place must end with the same globals, heap, screen and
  sound as the original's.

`tools/verify_port.sh` then runs the same games through the port itself (`port/mzport-headless`).

Time is deterministic: the rig only lets a tick pass when the game is waiting (a spin loop,
`WaitNextEvent`, `Delay`), and VBL tasks run as interrupts at fixed points. The port's headless mode
does the same, so runs can be compared byte for byte.

Three kinds of function, listed in `game/subs.txt`:

- **Compiled C** (A6 frame, stack arguments): plain C.
- **Hand-written assembly** (arguments and results in registers and flags): `void fn(Regs *r)` over
  a register block (`game/mzasm.h`), every register and flag exact, since callers rely on them.
- **Pascal runtime glue** (segment 3).

## The two games

Mazeworld Original shares much of Catacombs' engine. `tools/map_builds.py` pairs the functions of
the two builds and writes `game/orig_map.h`, which moves Catacombs' global and jump-table offsets
to Original's. Shared functions check `mz_original` where the games differ. Original's own code
is `fo_S<seg>_<offset>` in `game/orig_*.c`; its creatures are in `game/orig_creatures.c`.

## Names

Functions are `fn_S<segment>_<offset>` (Original's own: `fo_...`) and globals `G_<offset below A5>`
until a name is certain. Original's certain names are in `game/orig_names.h`.

## Tests

- `tests/*.txt`: scripted and random (`monkey`) games, menus, dialogs.
- `tests/mwo_*.txt`: Mazeworld Original. `mwo_level*_states.txt` and similar set creatures' states
  directly (`setr <record> 16 <state>`) to reach states play rarely does.
- `tests/recordings/`: real play, recorded with `mzplay`.
- The rig's autopilot (`-auto <goals>`, `harness/auto.c`) writes input for goals like
  `goto X Y`, `near R D`, `face R`, `fire N`, `wait N`.

Not reached by a test yet: Mazeworld Original's moving type $13 shot and the level 4 hunter's
$3D shot, Apple events, and Load / Save Game on a real file.

## Left out on purpose

The port always gives the game one 8-bit 640x480 screen, so code for other set-ups is left out:
drawing straight to 1, 4, 16 and 32-bit screens, desk accessories, Apple events other than
'quit', other monitors, system version checks, and Original's Print Order Form.

## Kept from the originals

Some quirks of the originals are kept, so the games behave exactly as before:

- Original's projection reads the word at low memory $30 (an exception vector), so the port's low
  memory holds the same value as the rig's.
- Lips (level 5) clears the word at address $E4 instead of a record field.

## Text

`mactb/font_data.c` is generated by `tools/fontgen.py`. The 9 point ASCII letters are Geneva 9's
shapes (Kelsey Higham's pixel copy, CC BY 3.0, `third_party/geneva9`); other sizes and characters
are an original stand-in with Geneva's line spacing.

## Places where the Toolbox is modelled

`FIDELITY` notes in `mactb/mactb.h` mark where behaviour is modelled rather than taken from Apple's
code: colour matching, palette slots, `Random`. They only affect the picture, and they are the same
in the rig and the port.
